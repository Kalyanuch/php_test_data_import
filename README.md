# Імпорт заявок із XLSX

Невеликий PHP-застосунок для імпорту 100 000 заявок із XLSX у SQLite або MySQL. Імпорт виконується синхронно в межах стандартного `max_execution_time=30`, без його програмного збільшення.

## Вимоги

- PHP 8.2 або новіший;
- PHP-розширення `dom`, `xmlreader`, `zip`, `pdo`;
- `pdo_sqlite` для запуску за замовчуванням або `pdo_mysql` для MySQL;
- Composer.

## Встановлення і запуск

```bash
composer install
cp .env.example .env
php -d upload_max_filesize=50M -d post_max_size=51M -S 127.0.0.1:8080 -t public
```

Відкрити `http://127.0.0.1:8080`, обрати XLSX і натиснути «Імпортувати».

Для Apache/FastCGI ліміти завантаження також задані у `public/.user.ini`. Якщо сервер не підтримує `.user.ini`, потрібно вручну встановити `upload_max_filesize=50M` та `post_max_size=51M` у його конфігурації. `max_execution_time` застосунок не змінює.

Застосунок автоматично читає `.env` із кореня проєкту. За замовчуванням він створює SQLite-базу `storage/database.sqlite` і таблиці під час першого запиту.

## Налаштування через `.env`

Скопіюйте шаблон і змініть потрібні значення:

```bash
cp .env.example .env
```

Доступні параметри:

| Параметр | Значення за замовчуванням | Призначення |
|---|---:|---|
| `APP_TIMEZONE` | `Europe/Kyiv` | Часова зона застосунку |
| `DB_DSN` | `sqlite:storage/database.sqlite` | PDO DSN для SQLite або MySQL |
| `DB_USER` | порожнє | Користувач БД; для SQLite не потрібен |
| `DB_PASSWORD` | порожнє | Пароль БД; для SQLite не потрібен |
| `UPLOAD_MAX_BYTES` | `52428800` | Прикладний ліміт завантаженого файлу в байтах |
| `IMPORT_BATCH_SIZE` | `500` | Кількість заявок в одному multi-row `INSERT` |

Приклад `.env` для MySQL:

```dotenv
APP_TIMEZONE=Europe/Kyiv
DB_DSN="mysql:host=127.0.0.1;port=3306;dbname=leads;charset=utf8mb4"
DB_USER=app
DB_PASSWORD=secret
UPLOAD_MAX_BYTES=52428800
IMPORT_BATCH_SIZE=500
```

Значення можна залишати без лапок або брати в одинарні чи подвійні лапки. Порожні `DB_USER=` і `DB_PASSWORD=` перетворюються на `null` у конфігурації. Рядки, що починаються з `#`, є коментарями. Змінні оточення, передані операційною системою, Docker або вебсервером, мають пріоритет над однойменними значеннями з `.env`; завдяки цьому production-секрети не потрібно зберігати у файлі.

Відносний шлях у SQLite DSN рахується від кореня проєкту, тому `sqlite:storage/database.sqlite` однаково працює у вебі та CLI незалежно від поточної директорії запуску. Файл `.env` внесений у `.gitignore` і не повинен потрапляти до репозиторію.

База MySQL має бути створена заздалегідь, а користувач повинен мати право створювати таблиці. Структури БД знаходяться у `database/schema.sqlite.sql` та `database/schema.mysql.sql`.

Імпорт також можна запустити з командного рядка:

```bash
php bin/import.php 'База даних.xlsx'
```

## Основні рішення

- Немає важкої XLSX-бібліотеки, яка будувала б у пам'яті об'єкти для кожної клітинки.
- У таблиці `leads` зберігається посилання на конкретний імпорт і номер вихідного рядка.
- Помилковий імпорт не залишає частково записані заявки.
- `external_id`, `import_id` і `status` проіндексовані для типових вибірок.
